# Contributing

Thanks for your interest in contributing! This document explains how you can help.

By participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md). By contributing, you agree that your contributions are licensed under the [Apache License 2.0](LICENSE).

## Ways to contribute

- **Report bugs** - open an issue with steps to reproduce, expected vs actual behaviour, and your environment.
- **Improve docs** - typo fixes and clarifications are always welcome.
- **Fix bugs / add features** - please open an issue first so we can discuss the approach before you invest time.

For security vulnerabilities, do **not** open a public issue. See [SECURITY.md](SECURITY.md).

## Reporting bugs

Before opening a new issue, search the issue tracker to see whether the problem has already been reported. If it has, add any new information to the existing issue.

When reporting a bug, include as much relevant detail as possible:

- Clear, detailed steps to reproduce the problem.
- Expected and actual behaviour.
- Version, operating system, and other relevant environment details.
- Logs, error messages, or other diagnostic information, with sensitive information removed.
- Root-cause analysis, technical observations, or potential approaches to a fix, if available.

## Requesting features

Open a feature request in the issue tracker, or upvote an existing request that describes the same need. Explain your use case, the behaviour you would like, and why it would improve your workflow.

## Pull requests

Thank you for considering contributing. Your efforts are incredibly valuable. To get started:

1. Fork the repository.
2. Create your feature branch: `git checkout -b feature/YourFeature`
3. Make sure all tests and linting pass.
4. Commit your changes: `git commit -am 'Add: YourFeature'`
5. Push to the branch: `git push origin feature/YourFeature`
6. Submit a pull request.

Keep pull requests focused and reasonably small. Describe **what** changed and **why**.

## Use of AI

You are welcome to use AI tools when writing code or preparing contribution materials. You remain responsible for the changes you submit, and we are responsible for what we merge.

Please keep communication with maintainers human-written:

- **Issues & Reviews:** Describe issues, reply to code reviews, and answer maintainer questions in your own words. Do not paste AI-generated responses.
- **PR Descriptions:** You may use AI to draft pull request descriptions, but they must be clearly labeled as AI-generated.
- **AI Quotes:** If you need to share output from an AI model, put it in a brief blockquote (`>`) and identify it as AI-generated.
- **Language Assistance:** If English is not your native language, you may use AI for translation or phrasing. Make sure the final result still reflects your own thoughts and ideas.

**Autonomous agents may not be used to open or update pull requests.** Someone who understands the proposed changes must remain involved throughout the process.
